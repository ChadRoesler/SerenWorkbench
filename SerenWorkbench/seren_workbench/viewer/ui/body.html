two gates: approving installs a tool — registered, visible, and switched off. You enable it separately on the Tool State tab. Read the runs line, not the description: that's what actually executes. Rejecting requires a critique, and the proposer reads it and can revise. A project is a piece of work: approving one agrees to its plan, its one directory and its download sites, and to nothing else - each need it lists is its own proposal below it, with its own switches. A revision changes an agreed project; read the diff.

the cabinet of plans: every project agreed through the queue, with where it stands and what has been done inside it. The journal is written by the model as it works - what it did, which files, what it checked, what is next - and is the no-repo git. The model may mark a project in progress or paused and may ask for done; you confirm done here, because done means the plan's "what done looks like" was met. A revision agreed against a done project reopens it.
